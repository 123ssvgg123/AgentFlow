02一次请求的链路

以 POST /api/chat 为例。全程用 thread_id 串联，日志里可以按它过滤出完整轨迹。

1
请求进入 前端带 Bearer JWT 调用 POST /api/chat
2
鉴权 api/auth.py 解出 tenant_id / user_id / role，作为后续数据隔离的键
3
生成 thread_id orchestrator.run() 入口，作为 Checkpointer 的隔离键
4
读长期记忆 加载门店偏好 + 顾客画像，注入 State
5
识别意图 LLM 输出 JSON；失败或非法则用 9 组关键词规则兜底，保证永远能路由
6
分流 单意图 → 直达一个 Agent；跨 Agent 或含“全流程” → Pipeline 串联
7
执行状态图 节点按需调用工具，工具失败进 degraded_tools 并降级继续
8
落快照 每个节点执行后 Checkpointer 自动存 State（PG 模式下写入 checkpoints 表）
9
汇总返回 _aggregate() 产出 answer / pending_actions / degraded_tools，走 JSON 或 SSE

04三层记忆

短期记忆存「过程」，长期记忆存「事实」。Checkpointer 不能替代数据库做统计。

层载体隔离键存什么保留
短期LangGraph Checkpointer（PG 表 / 内存）thread_id运行时 State 快照，支持多轮与断点续传90 天
长期PostgreSQL 6 张业务表（降级 JSON 文件）tenant_id + user_id门店偏好、顾客画像、评价分析、食材消耗永久 / 730 天
合规compliance_log + order_status_logtenant_id + user_id过敏原告知与确认、订单全链路流转3 年 / 90 天

写入语义：UPSERT 幂等 门店偏好 / 顾客画像一店一人一行； 原子累加 食材消耗用 ON CONFLICT 增量更新，多进程并发也正确。

05降级设计

「有依赖更强，无依赖也能跑」。所有降级都会写进响应的 degraded_tools 字段。

依赖缺失时行为代码位置
langgraph降级为顺序执行器，条件边退化为 if/elsebase_agent.py
LangGraph 静默中断未达终态时自动补跑一次顺序执行_reached_terminal()
DeepSeek API所有 LLM 工具走规则引擎分支llm_client.py
PostgreSQL长期记忆 → JSON 文件；Checkpointer → 内存store.py / checkpointer.py
Redis缓存降级进程内字典（启动会多等约 48 秒）cache.py
外部知识源 / 联网搜索回落内置知识库（法规 + 菜品 + 营养）；联网失败走 24h 缓存mcp_tools.py
POS / KDS返回 Mock 数据，流程仍可走通external_api.py
LangSmith / Prometheus追踪与指标退化为 no-op，零开销tracing.py / metrics.py
